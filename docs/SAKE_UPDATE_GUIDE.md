# 新しい日本酒をメニューへ追加する手順

写真を追加してから、Webメニュー、Googleスプレッドシート、公開ページまで反映するための人向け手順書です。

## 最初に知っておくこと

現在のWebメニューは、Googleスプレッドシートではなく、GitHubの `menu.csv` を直接読み込んでいます。

```text
酒情報スプレッドシート ── 手動で同期 ──> menu.csv ── GitHub Pages ──> Webメニュー
                                              │
状態管理スプレッドシート ── GAS API ──────────┘
  soldOut / orderEnabled / hidden
```

そのため、酒情報スプレッドシートだけを更新しても公開ページは変わりません。`menu.csv` を更新してGitHubへpushするところまで必要です。

- 公開ページ: <https://kerroggu.github.io/SakeMenu/>
- 酒情報管理シート: <https://docs.google.com/spreadsheets/d/1uYTCXtAmor6ZzrItT2POE25LvmWec1D75Eaco3ZaDFA/edit?gid=0#gid=0>
- 状態管理用スプレッドシート: <https://docs.google.com/spreadsheets/d/1W3_a2qvZ6z6cpHRbyxMqZKdy-TH7Qubl1PHIxbGwS04/edit?gid=0#gid=0>

## 用意するもの

- ボトル正面の写真
- できれば裏ラベルの写真
- 追加した写真を入れた日付フォルダ。例: `photo/20260801/`
- 追加しない写真がある場合は、そのファイル名の一覧

裏ラベルがあると、酒米、精米歩合、アルコール度数、生酒・火入れなどを正確に登録できます。

## AIへ依頼するときの書き方

次のように伝えると作業範囲が明確になります。

```text
photo/20260801 に新しい日本酒の写真を入れました。
銘柄と商品情報を調べ、ラベル画像をトリミング・色補正して、
menu.csv と状態管理シートへ追加し、公開ページまで反映してください。

次の写真は追加しないでください。
- PXL_xxxxxxxxx.jpg
- PXL_yyyyyyyyy.jpg
```

追加情報が分かる場合は、購入価格、入手店、ヴィンテージ、限定頒布会名なども一緒に伝えてください。

## 作業の流れ

### 1. 写真を追加する

1. `photo/` の下に日付フォルダを作ります。
2. 元写真をそのフォルダへ入れます。
3. 同じ酒の表ラベルと裏ラベルは、削除せず両方入れて構いません。
4. メニューへ載せない写真は、ファイル名をAIへ明示します。

元写真は保管用です。通常、GitHubへは公開しません。

### 2. 銘柄情報を確認する

ラベルと信頼できる商品ページから、次の情報を確認します。

- 表示名と正式商品名
- 酒蔵と都道府県
- 純米、吟醸、生酛などのタイプ
- 生酒、無濾過、原酒、火入れ
- 酒米と精米歩合
- アルコール度数
- 味わい、おすすめ温度、ペアリング
- 価格。分からなければ空欄で構いません

限定品は、年やロットが違う商品情報を混ぜないようにします。確認できない項目は推測せず空欄にします。

### 3. ラベル画像を作る

元写真からボトルまたはラベルを縦長に切り出します。

- 商品名が読めること
- 傾きが不自然でないこと
- 暗すぎたり、色が黄・青に偏ったりしていないこと
- ラベルの文字や模様が加工で変わっていないこと
- ファイル名がメニューのIDと対応していること

保存先は `labels/` です。軽量化した画像は `labels/web/` に置きます。

### 4. `menu.csv` に追加する

`menu.csv` の末尾へ1銘柄1行で追加します。列は次の順番です。

```csv
Id,Name,SearchName,Image,Price,Tsukuri,Hiire,Sakamai,Prefecture,Shuzou,Seimai,Status,Flavor,Temperature,Pairing,Alcohol
```

重要なのは `Id` です。英小文字、数字、ハイフンで一意にし、一度公開した後は変更しません。注文、評価、売切れ情報がこのIDに紐づくためです。

画像パスの例:

```text
labels/new-sake-id.png
labels/web/new-sake-id.jpg
```

`data.js` の `menuVersion` も更新します。これを変えることで、古いCSVがブラウザキャッシュに残るのを防ぎます。

### 5. 状態管理シートへ追加する

状態管理用スプレッドシートの `menu` シートを開きます。列は次の4列です。

```csv
id,soldOut,orderEnabled,hidden
```

新しい酒の初期値は次のとおりです。

```csv
new-sake-id,false,true,false
```

各チェックボックスの意味:

- `soldOut`: チェックすると、メニューに残したまま「売切れ」にする
- `orderEnabled`: チェックを外すと「受付停止」にする
- `hidden`: チェックすると、Webメニューから完全に隠す

新規行だけを追加してください。`gas/menu.sample.csv` を既存シート全体へ貼り直すと、現在の売切れ状態などを消す可能性があります。

`gas/menu.sample.csv` にも同じ新規IDを追加して、リポジトリ内の見本を最新にします。

### 6. 酒情報管理シートも同期する

酒情報管理シートを正本として使い続けるため、同じ銘柄情報を追記します。ただし、現状ではこのシートからWebサイトへの自動同期はありません。公開には `menu.csv` の更新も必要です。

AIにシートを直接編集させる場合は、CodexのGoogle Driveプラグイン／コネクタをGoogleアカウントで認証し、接続後に新しいCodexセッションを開始します。Codexへ共有する専用メールアドレスはありません。また、シートを「リンクを知っている全員が編集可」にするのは避けてください。

### 7. GASの再デプロイが必要か判断する

日本酒の行を追加しただけなら、通常はGASの再デプロイは不要です。

次の場合は `gas/Code.gs` をApps Scriptへ反映し、再デプロイが必要です。

- `hidden` など新しい列の読み取り処理を追加した
- 注文、評価、通知の処理を変更した
- Web APIの返すデータを変更した

Apps Scriptでは、コードを保存した後に `デプロイ` → `デプロイを管理` → 鉛筆アイコン → `新しいバージョン` → `デプロイ` の順で更新します。保存だけでは公開中Webアプリは更新されません。

既存デプロイの更新を推奨します。この方法ならWebアプリURLは変わりません。誤って「新しいデプロイ」を作ってURLが変わった場合は、新しい `/exec` URLを `data.js` の `gasAppUrl` に設定し、GitHub Pagesへcommit・pushします。ブラウザに古い `data.js` が残る場合に備え、`index.html` のスクリプト読込クエリも更新します。

稼働中のApps ScriptコードがGitHub版より長い場合は、全体を上書きする前に差分を確認します。`notification_queue` やDiscord再試行処理などがApps Script側だけにある場合は、それらを残し、変更対象の関数だけを差し替えます。

### 8. 公開前に確認する

- 追加件数とラベル画像数が合っている
- スキップ指定した写真が追加されていない
- 同じ酒が重複していない
- 画像と銘柄名が一致している
- 画像が表示される
- 酒名で検索できる
- CSVの列がずれていない
- 状態管理シートのIDと `menu.csv` のIDが完全一致している
- `soldOut`、`orderEnabled`、`hidden` が期待どおり動く

### 9. GitHubへ公開する

変更したメニュー関係のファイルだけをコミットし、`main` へpushします。写真原本や別作業中のファイルを一緒にコミットしないようにします。

GitHub Pagesへの反映には数分かかることがあります。反映後、公開ページをスマホでも確認します。

## ページが変わらないとき

1. GitHubへcommit・pushしたか確認する。
2. `main` ブランチに変更が入っているか確認する。
3. 公開中の `menu.csv` に新しい酒があるか確認する。
4. `data.js` の `menuVersion` を変更したか確認する。
5. 10分ほど待ち、ブラウザを強制再読み込みする。
6. 画像パスの大文字・小文字と拡張子を確認する。

酒情報スプレッドシートだけを更新しても、現在の公開ページは変わりません。

## チェックボックスが効かないとき

1. 状態管理シートのタブ名が `menu` になっているか確認する。
2. ヘッダが `id,soldOut,orderEnabled,hidden` になっているか確認する。現在のコードは `Hidden` も認識しますが、小文字 `hidden` を推奨します。
3. `id` が `menu.csv` と完全一致しているか確認する。
4. 最新の `gas/Code.gs` がWebアプリへデプロイされているか確認する。
5. `data.js` の `gasAppUrl` が現在のWebアプリURLか確認する。
6. ブラウザで `<gasAppUrl>?action=menuStatus` を開く。
7. 対象銘柄に `"hidden":true` があればGASは正常。`hidden` 項目自体がなければ旧バージョンまたは旧URLを参照している。
8. APIが正常でも表示される場合は、公開中の `data.js` とブラウザキャッシュを確認する。

### 2026年8月の実例

GASを「新しいデプロイ」として公開したためURLが変わり、シートと新APIは正しいのに、Webページだけが旧GAS URLを参照し続けた事例がありました。`data.js` の `gasAppUrl` を新URLへ変更し、`index.html` の `data.js`／`app.js` 読込URLへ版数を付けることで解消しました。
